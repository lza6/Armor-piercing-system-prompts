## 官方机制 → 实际写作动作

| 官方机制 | 本技能中的动作 | 验收问题 |
| --- | --- | --- |
| 先定义所需图像，再描述主体、构图与限制 | 提取最小画面契约；把抽象审美变成可见特征 | 能否画出数量、位置与层级？ |
| 格式服从可维护性 | 短任务用一段，多约束任务分节 | 每句话是否影响结果或约束？ |
| 明确媒介、材料、照明、人物动作 | 指定手的交互、视线、取景范围及光源 | 是否存在相互矛盾的姿态或镜头？ |
| 精确文字必须明示并检查 | 引号保留原文，指定次数与排版 | 拼写、字数和出现次数是否符合输入？ |
| 编辑要说明改变与保持的部分 | 先列改变项，再固定关键外观及布局 | 是否发生非目标改变？ |
| 多张输入各有用途 | 按输入次序给身份、产品、风格、背景分配角色 | 每个元素来自哪里、去哪里？ |
| 利用上一结果继续窄范围编辑 | 下一轮输入使用上次输出，并重复关键保留项 | 能否知道是哪条修改改善了结果？ |
| 事实图像也需事实验收 | 逐项检查数据、标签、箭头和科学关系 | 好看是否掩盖了错误关系？ |
| 透明度需要真实输出设置和文件检查 | 透明背景 + PNG/WebP + alpha 验收 | 是否只是画了棋盘格？ |
| 先满足质量，再优化延迟 | 固定输入做 Flare/Sunburst 和 quality 对比 | 是否有自己的实测证据？ |

更多对应：漫画需逐格叙事，角色系列需要重复使用外观锚点；UI 和幻灯片应描述真实成品的布局、层级与内容；草图转写实应固定布局和透视，再增加材料与光线。

## 模型名称核验

- GPT Image 2.5 Flare：API ID `gpt-image-2.5-flare`，官方定位偏向速度。
- GPT Image 2.5 Sunburst：API ID `gpt-image-2.5-sunburst`，官方定位偏向高要求质量与精确编辑。
- 未指定取舍时，本技能不强行在纯提示词中推荐模型。用户需要设置时，按“快速日常 → Flare；复杂质量/编辑需求 → Sunburst”给出候选并说明要实测。
- 同名 quality 档位不能证明两款模型结果或延迟相同；更高档位也不保证每个提示词都更好。定价、账户可用性和实际延迟必须另行核验。

## 本技能的设计选择

以下是面向写作的封装，并非文档规定：默认中文、一个提示词优先；只要最终提示词时隐藏辅助说明；最多两个关键问题；按场景选模块；用一至三条说明披露默认值；把诊断、模板和执行分开；附离线参数检查器。

没有把官方示例里的虚构市场数据、原角色设定、品牌名或旧模型代码带入通用模板。也没有因为示例写了某个 quality 档位，就将其当成所有任务的硬性默认值。

## 更新与证据规则

稳定写作原则可以离线使用。用户问当前模型、要求运行 API、或涉及本快照未覆盖的参数时，优先读取当前官方文档；不可访问时明确快照日期与未确认项，仍可完成与其无关的提示词写作。

更新时记录：来源页面、核验日期、具体改变、受影响文件及回归用例。参数和示例应同时更新；不要仅将日期改成今天。图片质量、文字正确率和延迟改善需要实际生成结果，不能由本文件或结构检查推导。
