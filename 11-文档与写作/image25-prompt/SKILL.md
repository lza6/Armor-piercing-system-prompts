# Image 2.5 Prompt

将创作意图变成能复制使用、能核对结果的图片提示词。与用户使用同一种语言；默认完成其要求，不强制翻译成英文或统一改成JSON。

## 任务边界

- 写提示词、改提示词、检查提示词：直接交付文本，不调用生图、不要求API Key。
- 用户同时明确要求出图：先完成提示词，再交给环境实际可用的生图能力；尊重用户指定模型与平台。没有对应能力时交付提示词并说明缺口。
- 工具未暴露后端版本时标注“模型版本未暴露”；在提示词中写模型名不会切换模型。不得把宿主默认生成包装成指定版本实测。
- 处理参考图前先查看它；未收到或无法查看的图不得描述成已检查。可先写标明输入依赖的模板，执行编辑前需取得实际图片。
- 本技能处理静态图。视频首帧是单个明确时刻。生成图不自动等于可编辑PSD、SVG、三维模型或视频。

## 决策流程

1. 确定新图、参考创作、局部编辑、多轮迭代或结果诊断。提取用途、必需文案、画幅和参考职责。
2. 完整要求直接组织；只有缺失信息会实质改变结果时才提问。可推断的风格用简短假设处理，不擅自增加品牌、剧情、人物或大批变体。
3. 简单场景用自然段，复杂布局和多参考用分组，用户已有JSON就保留可维护结构。不把格式变化冒充能力提升。
4. 视觉要求写入提示词，API设置另列。先保证用户最重要的限制，再减少冲突的次要细节。
5. 编辑写清本次变化和保留内容。多图注明各自职责，以及冲突时以哪张为准。
6. 交付完整提示词，按任务附关键检查项。若用户只要提示词，只输出提示词。
7. 用户提供生成结果后，对照实际画面指出具体问题，给最小修复提示词。没有图时只做文字审查，不做视觉验收。

## 输出协议

默认输出：
- **可直接使用的提示词**：一段或一个完整文本代码块。
- **参考图说明**：只有多图或输入歧义时附上。
- **执行建议**：用户需要平台、模型或API设置时附上，区分建议与已执行。
- **关键验收点**：围绕本任务易错位置，通常2–4项。

系列素材先定义共用设定与逐张变化。需要独立复制的每条提示词带上关键共用约束，不让单独复制后失去人物或品牌定义。

修复只针对观察到的问题。发布案例需保留原提示词、原图、实际执行方式与已知失败，不挑图制造胜率。

## 需要保持的判断

- 字体、摄影机、8K、JSON键名是描述线索，不是实际设置或质量保证。
- 数值、标签与关系需要核对；用户没给事实数据时，不编造精确数据填版面。
- 涉及左右手或站位时才区分人物自身左右与画面左右，并检查二者不冲突。
- 要求文字唯一时说明哪些表面允许文字；包装标签、倒影、背景招牌都可能造成重复。
- 精确保留区域时说明提示词与遮罩不能保证逐像素不变；可建议局部合成，但不承诺工具未提供的能力。
- 从最近通过验收的版本继续，避免在已漂移的版本上不断加码。重试次数、批量规模和费用遵循用户授权。
